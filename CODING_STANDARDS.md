# Coding standards

Rules reviewers keep flagging. Each has its reason.

- **Toasts and Undo toasts are polite live regions (`role="status"`), not alerts.** `ToastProvider` defaults to `role="alert"`; pass `polite: true` in the toast options to get `status`. An alert interrupts the screen reader mid-sentence; a toast is information, not an emergency.
- **Tests use fake timers (`vi.useFakeTimers`), never real waits or `setTimeout` sleeps.** Real waits make suites slow and flaky under load.
- **Snapshots and date assertions never depend on today's date.** Pin the clock with fake timers or pass fixed dates, or the test breaks the day after it is written.
- **A component used by more than one page lives in `apps/web/src/components`.** Page-local copies drift apart; `pages/<Page>/components` is for single-page code only.
- **Undo reverses only what the action created.** Reversing more deletes Member data the action never touched.
- **New copy goes in en, ro and da, with ro plural forms (`_one`, `_few`, `_other`; `_few` covers 0, fractions, and counts whose last two digits are 01-19 except 1 itself (0, 2-19, 101-119, ...; 20, 100 and 120 are `_other`)), using `GLOSSARY.md` terms.** A missing locale shows raw keys, and without `_few` Romanian counts such as 0 or 12 read wrongly.
- **Gator speaks only where Gator is drawn.** Copy beside a Gator image may use Gator's first person ("I spotted 6 things!"); toasts, empty states and errors elsewhere keep the app's plain voice, and Gator's lines name only real features. Spoken Siri replies and permission prompts name the app, PantryGator.
- **Inside a `Sheet` or `Dialog`, never focus a field that is present when it opens: no `autoFocus` and no focusing in `onEntered`. Pass `initialFocus` instead.** Below `md`, `initialFocus` keeps a text field unfocused so the phone keyboard does not jump the sheet while it slides in (ADR 0039). `initialFocus` never moves focus the Member has already moved to a control inside the sheet; with no target, focus goes to the sheet's surface. A field revealed by the Member's tap inside an open sheet may take focus.
- **Lint with the right tool: `oxlint` in `apps/web` and `packages/ui` (shared config `.oxlintrc.json` at the root), eslint in `apps/api`.** Running the wrong one passes silently or reports nothing; use `npm run lint -w <workspace>`. Test files may not use `setTimeout`/`setInterval` (lint error): use `vi.useFakeTimers()`, `waitFor`/`findBy*`, or await the real promise. The pre-commit hook lints staged files first (`lint-staged.config.mjs`).

## Design system

`packages/ui` (`@pocket-pantry/ui`) holds the components and the Theme tokens. Its layout is in `docs/agents/codebase-map.md`; ADR 0010 explains how Themes work.

- **Build from `@pocket-pantry/ui`, not from `@mui/material`.** Look in `atoms/`, `molecules/` and `organisms/` before writing a new component, and import from the package root, not a deep path (tests may import `@pocket-pantry/ui/test/colour`, the one other export). Our wrappers carry Theme styling and behaviour plain MUI does not (`Sheet` and `Dialog` handle focus per ADR 0039). If a primitive is missing, add a wrapper to `packages/ui` rather than importing MUI in `apps/web`.
- **A component goes in `packages/ui` when it has no app knowledge: no API calls, no i18n keys, no domain data loading.** It takes its text and data as props. Anything that reads `lib/`, calls `t()` or knows a domain type such as `RecipeTag` stays in `apps/web/src/components` (or the page's own folder). This keeps the package usable from Storybook without the app.
- **Colours, radii, shadows, borders and fonts come from Theme tokens, never literals.** Use the `themeVars` helpers: `palette('pp-accent')`, `color.*`, `radius.*` (`nestedRadius` for a radius inside another), `shadow.*`, `border.*`, `bodyFont`, `displayType`, or sx palette paths such as `'pp.accent'`. A hex value, `rgb()` or a pixel radius looks right in one Theme and wrong in the other two (`warm`, `minimal`, `dark`). New code doesn't import the legacy `tokens` object; it exists only so old importers keep working.
- **A new colour token is added to all three Themes and, if it is text or an accent on a fill, to the pairs in `theme/contrast.test.ts`.** `ThemeTokens` makes a missing one a type error, but only the test catches a colour below 4.5:1 contrast in one Theme.
- **Never read `theme.palette.mode` to choose a colour; use `theme.vars` or the helpers above.** Inside a forced subtree such as the Scan screen, the theme object describes the root's scheme, not the one on screen (ADR 0010).
- **Clear device edges with the safe-area rules and the Dock helpers, not fixed offsets (ADR 0040).** Sticky headers stick at `top: env(safe-area-inset-top)`, page gutters are `max(20px, env(safe-area-inset-left/right))`, and anything floating above the Dock uses `aboveDock(height)` (or `DOCK_BOTTOM` / `DOCK_HEIGHT`). A hardcoded `bottom: 100px` sits under the home indicator on one phone and floats too high on another.
- **Reuse `focusRing` / `insetFocusRing` for custom focusable elements and `visuallyHidden` for screen-reader-only text.** Hand-made outlines drift from the Theme accent, and `display: none` hides text from screen readers too.
- **Motion respects `usePrefersReducedMotion`.** Slides, springs and Gator animations get a still or cross-fade alternative when it is on; some Members get motion sick.
- **A new `packages/ui` component ships with a `*.stories.tsx` beside it** that shows its states (at least default, disabled or empty, and long text). Storybook is where a Theme or contrast regression shows up before it reaches a page.
