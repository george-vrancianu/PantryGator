# Coding standards

Rules reviewers keep flagging. Each has its reason.

- **Toasts and Undo toasts are polite live regions (`role="status"`), not alerts.** `ToastProvider` defaults to `role="alert"`; pass `polite: true` in the toast options to get `status`. An alert interrupts the screen reader mid-sentence; a toast is information, not an emergency.
- **Tests use fake timers (`vi.useFakeTimers`), never real waits or `setTimeout` sleeps.** Real waits make suites slow and flaky under load.
- **Snapshots and date assertions never depend on today's date.** Pin the clock with fake timers or pass fixed dates, or the test breaks the day after it is written.
- **A component used by two or more page areas lives in `apps/web/src/components`, in the GLOSSARY-named group it belongs to (`recipe/`, `pantry/`, ...); a component used by one area lives in `pages/<Area>/components`.** Page-local copies drift apart, and a shared folder full of one-page code hides how far a change reaches. Nothing outside `pages/X` imports `pages/X/components` or `pages/X/hooks`, and `components/` and `lib/` never import `pages/` (ADR 0044).
- **New components get their own folder, with the test beside the file: `Foo/Foo.tsx`, `Foo.test.tsx`, and no `index.ts`.** A test lives beside what it renders, so a module's test is found from the module. Don't split an existing page test just to fill folders.
- **Undo reverses only what the action created.** Reversing more deletes Member data the action never touched.
- **New copy goes in en, ro and da, with ro plural forms (`_one`, `_few`, `_other`; `_few` covers 0, fractions, and counts whose last two digits are 01-19 except 1 itself (0, 2-19, 101-119, ...; 20, 100 and 120 are `_other`)), using `GLOSSARY.md` terms.** A missing locale shows raw keys, and without `_few` Romanian counts such as 0 or 12 read wrongly.
- **Gator speaks only where Gator is drawn.** Copy beside a Gator image may use Gator's first person ("I spotted 6 things!"); toasts, empty states and errors elsewhere keep the app's plain voice, and Gator's lines name only real features. Spoken Siri replies and permission prompts name the app, PantryGator.
- **Inside a `Sheet`, never focus a field that is present when it opens: no `autoFocus` and no focusing in `onEntered`. Pass `initialFocus` instead.** Below `md`, `initialFocus` keeps a text field unfocused so the phone keyboard does not jump the sheet while it slides in (ADR 0039). `initialFocus` never moves focus the Member has already moved to a control inside the sheet; with no target, focus goes to the sheet's surface. A field revealed by the Member's tap inside an open sheet may take focus.
- **Never hand-build a Sheet's title, close or actions; pass `title`, `primary`, `secondary` and `destructive` to `Sheet` (ADR 0043).** Close is the X; there is no Cancel button. Actions go in the footer, with one primary on the right and at most one secondary on the left. Destructive actions are a danger link at the bottom of the content, unless destroying is the Sheet's purpose. Use Save to commit an edit, a specific verb to create or act, and Done to confirm a choice. A Sheet's primary is never the gold key. Each hand-built footer or Cancel pill drifts from the others; the audit behind ADR 0043 found five kinds of close and both button orders. `Sheet` has no `header`, `footer` or `label`, so the type checker refuses hand-built chrome. A Sheet inside a screen that forces its own Theme or turns its content (the camera) is mounted under `SheetContainerProvider`, given that element, so it keeps the Theme and the turn; mount the Sheet after the element exists, or it opens on the body.
- **Lint with the right tool: `oxlint` in `apps/web` and `packages/ui` (shared config `.oxlintrc.json` at the root), eslint in `apps/api`.** Running the wrong one passes silently or reports nothing; use `npm run lint -w <workspace>`. Test files may not use `setTimeout`/`setInterval` (lint error): use `vi.useFakeTimers()`, `waitFor`/`findBy*`, or await the real promise. The pre-commit hook lints staged files first (`lint-staged.config.mjs`).

## Design system

`packages/ui` (`@pocket-pantry/ui`) holds the components and the Theme tokens. Its layout is in `docs/agents/codebase-map.md`; ADR 0010 explains how Themes work.

- **Build from `@pocket-pantry/ui`, not from `@mui/material`.** Look in `atoms/`, `molecules/` and `organisms/` before writing a new component, and import from the package root, not a deep path (tests may import `@pocket-pantry/ui/test/colour` and `@pocket-pantry/ui/test/authoredCss`, the only other exports). Our wrappers carry Theme styling and behaviour plain MUI does not (`Sheet` handles focus per ADR 0039). If a primitive is missing, add a wrapper to `packages/ui` rather than importing MUI in `apps/web`.
- **A component goes in `packages/ui` when it has no app knowledge: no API calls, no i18n keys, no domain data loading.** It takes its text and data as props. Anything that reads `lib/`, calls `t()` or knows a domain type such as `RecipeTag` stays in `apps/web/src/components` (or the page's own folder). This keeps the package usable from Storybook without the app.
- **Colours, radii, shadows, borders and fonts come from Theme tokens, never literals.** Use the `themeVars` helpers: `palette('pp-accent')`, `shade.*` (hover and row mixes such as `shade.accentHover`), `color.*`, `radius.*` (`nestedRadius` for a radius inside another), `shadow.*`, `border.*`, `bodyFont`, `displayType`, or sx palette paths such as `'pp.accent'`. A hex value, `rgb()` or a pixel radius looks right in one Theme and wrong in the other (`light`, `dark`).
- **A new colour token is added to both Themes (Light and Dark) and, if it is text or an accent on a fill, to the pairs in `theme/contrast.test.ts`.** `ThemeTokens` makes a missing one a type error, but only the test catches a colour below 4.5:1 contrast in one Theme.
- **Never read `theme.palette.mode` to choose a colour; use `theme.vars` or the helpers above.** Inside a forced subtree such as the Scan screen, the theme object describes the root's scheme, not the one on screen (ADR 0010).
- **Clear device edges with the safe-area rules and the Dock helpers, not fixed offsets (ADR 0040).** Sticky elements inside the shared layout's sheet stick at `top: 0` of the scroller (the top inset is already cleared above it, ADR 0040 amendment); outside it (full-screen views) they stick at `top: env(safe-area-inset-top)`. Inside a `Sheet`, top controls (search, filters) go in its `toolbar` slot, never a hand-built sticky wrapper: `Sheet` draws the fill, padding and divider, and the toolbar is outside the scroll so it cannot cover the focused row. The toolbar is for search and filters, never actions (ADR 0043). Page gutters are `max(16px, env(safe-area-inset-left/right))` on phones (`PAGE_GUTTERS` in `LayoutFrame`; `md` and up use 48px), and anything floating above the Dock uses `aboveDock(height)` in CSS. JavaScript geometry (popover or scroll limits) reads the real inset with `dockBottomPx()` / `readSafeInsets()`, never the bare `DOCK_BOTTOM` (26px). A full-width bar that replaces the Dock pads the page by `plusBottomInset(N)` (its height plus the inset). A hardcoded `bottom: 100px` sits under the home indicator on one phone and floats too high on another.
- **Reuse `focusRing` / `insetFocusRing` for custom focusable elements (`canopyFocusRing` / `canopyFocusRingStyle` for controls on the Canopy and the Dock, where the accent is hard to see) and `visuallyHidden` for screen-reader-only text.** Hand-made outlines drift from the Theme accent, and `display: none` hides text from screen readers too.
- **Motion respects `usePrefersReducedMotion`.** Slides, springs and Gator animations get a still or cross-fade alternative when it is on; some Members get motion sick.
- **A new `packages/ui` component ships with a `*.stories.tsx` beside it** that shows its states (at least default, disabled or empty, and long text). Storybook is where a Theme or contrast regression shows up before it reaches a page.
